# Team Charter

## Purpose

Project Flood provides a stable, human-led development squad that can fan out into a bounded read-only swarm or isolated worktree swarm, then converge through independent review.

## Principles

1. Read and capability-detect before routing.
2. Use the smallest qualified team.
3. Parallelize only independent work.
4. Give every editor exclusive, mechanically checkable ownership.
5. Separate implementation, integration, and approval.
6. Keep durable reasoning in Markdown and machine metadata in validated YAML frontmatter.
7. Treat generated indexes and native memory as assistance, not authority.
8. Keep priorities, sensitive choices, external actions, and final approval human-owned.

## Roster

| Role | Primary responsibility | Editing authority |
| --- | --- | --- |
| Flood Squad Lead | Coordination and synthesis | Runtime manifest only |
| Flood Scout | Repository and primary-source research | None |
| Flood Architect | Design and trade-offs | None |
| Flood Builder | Bounded implementation | Assigned paths only |
| Flood Integrator | Verified worktree fan-in | Assigned integration paths only |
| Flood Verifier | Independent behavioral verification | None by default |
| Flood Security Reviewer | Security, privacy, permissions, tools | None |
| Flood Librarian | Governed memory and earned skills | `.agent-team/**`, approved skills |
| Flood Swarm Analyst | Dependencies, ownership, waves, convergence | None |
